A Claude Code plugin

Claude forgets between chats. quest-system makes every lesson it learns load into the next session.

RPG-themed feature management for Claude Code: plain markdown files in your repo that Claude reads before it works and writes before it stops.

Why it sticks

Same project, same two chats — you're adding avatar upload to your web app. The only difference between these two timelines is whether anything is remembered.

Without quest-system

  1. Monday — chat 1

    You build the upload form. Mid-way, a surprise: HEIC photos from iPhones decode blank on Safari. Twenty minutes of debugging later you fix it — resize client-side to 512px JPEG — and you decide that's the rule from now on.

  2. chat ends — the bug, the fix, the decision: all gone
  3. Wednesday — chat 2

    “Now add avatar cropping.” Claude happily suggests server-side resizing — the decision you already made, unmade. The new code path skips the HEIC fix, the bug ships a second time, and you're typing the same explanation again.

every chat starts at zero

With quest-system

  1. Monday — chat 1

    Same build, same HEIC surprise, same fix. One difference: the session ends with /make-camp, and the trap plus your resize decision are written into the repo.

  2. lessons land in .ai-context/ — committed with your code
  3. Wednesday — chat 2

    /embark briefs the new chat before any code:

    “Danger: HEIC decodes blank on Safari → resize client-side to 512px JPEG. Decision on record: resize before upload.”

    Cropping gets built on top of the fix. Nothing re-explained, nothing regressed, your rule still the rule.

every chat starts ahead

And when the feature ships, those lessons distill into a project-wide registry — so the next feature's first briefing starts smarter too.

How it works

Five commands, one loop — here's a real week. You're building user avatars, and on day two you hit a bug: HEIC photos decode blank on Safari. Watch where that lesson goes.

quest
a feature or epic you're building
expedition
one work session on it
scrolls
markdown files in your repo that Claude reads and writes
XP
a score computed from what you actually recorded
realm
the app target a quest is scoped to (for mono-repos)
  1. Day 1

    /new-quest user-avatars

    The feature becomes a quest: five markdown files appear in your repo, ready to hold everything Claude learns.

  2. Day 1

    /counsel-quest

    Scout agents explore the codebase; the plan is locked before any code is written.

  3. Day 2–3

    ↻ the session loop — repeat until built

    1. /embark

      The session opens with a briefing built from the files: status, known pitfalls, decisions on record.

    2. Mid-session, the real world bites: HEIC photos decode blank on Safari. The fix — resize client-side before upload — is written down the moment it's found.

    3. /make-camp

      The session ends by writing everything back: journal entry, the HEIC lesson, XP.

    Day 3, a brand-new chat: /embark's briefing already warns about HEIC before you ask. No re-explaining.

  4. Day 4

    /complete-quest

    The feature ships. Its lessons distill into project-wide memory — the next feature's first briefing starts smarter.

Side quests

Mid-work you spot a one-line bug that has nothing to do with today's focus. Fixing it now derails the session; ignoring it loses it forever. Side-quests are the third option.

  1. /side-quest "avatar border clips" Captured in one scroll. Your active quest does not change.
  2. (another chat) open the NOTE Another chat — even another day — picks it up by name; one scroll holds everything it needs.
  3. /close-side-quest What was learned distills UP into the parent quest's scrolls.

XP

Discipline needs a reason. Every camp and every completed quest pays out EXP — computed from what you actually recorded, not from vibes.

Completing an expedition5

Base reward100
Per module (plan item) conquered25
Per expedition logged10
Per danger / per oath15 / 20
Per scroll split (a file outgrew 500 lines and was divided)50
Clean sweep (no open questions) / speed run (≤3 sessions)+75 / +50

Fifty levels from Apprentice Coder to Transcendent Engineer, fifteen badges — and the numbers above are the real formula, straight from the system's own ledger. The demo quest earns 405 EXP: two camps (25 + 15) plus completion — 100 base + 2 modules×25 + 2 expeditions×10 + 2 dangers×15 + 2 oaths×20 + 75 clean sweep + 50 speed run = 365. Install

  • Plain markdown files + slash commands. No server, no database, no build.
  • Everything lives in .ai-context/ in your repo — committed, reviewable, greppable.
  • vs CLAUDE.md: that's static always-on instructions. Quests are per-feature working memory with a lifecycle — plan, work, record, distill.
  • The RPG flavor lives in filenames and banners. Your code and commits stay normal.

Two commands in Claude Code, then restart and start your first quest. 

/plugin marketplace add findexu/finpack-claude
/plugin install quest-system@finpack-claude

Restart Claude Code, open your project, and run /new-quest. Prefer owning the files? The repo can also be cloned — /install-quest-system bootstraps any project; the README is the canonical install doc.
