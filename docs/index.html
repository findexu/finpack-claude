A Claude Code plugin

Claude forgets between chats. quest-system makes every lesson it learns load into the next session.

RPG-themed feature management for Claude Code: plain markdown files in your repo that Claude reads before it works and writes before it stops.

Why it sticks

The moment it clicks is the second session. A brand-new chat, zero shared history — and the briefing already knows last week's trap.

Without quest-system

“Here's the context again: we're building avatars, last time we found that HEIC photos break on Safari, we decided to…” — ten minutes of re-explaining, every single chat. Forget once and the same bug bites twice.

With quest-system

/embark answers before you ask:

“Quest dangers: HEIC decodes as 1×1 on Safari canvas → resize client-side to 512px JPEG. Decisions on record: resize before upload.”

This chat never saw last week. The files did.

And when the feature ships, those lessons distill into a project-wide registry — so the next feature's first briefing starts smarter too.

How it works

Five commands, one loop. Each one reads the scrolls before it acts and writes them before it stops — so no chat ever starts from zero.

  1. /new-quest A feature becomes a quest: five persistent scrolls that outlive every chat.
  2. /counsel-quest Scout agents explore the codebase; the battle plan is locked before any code.
  3. /embark A work session opens with a briefing built from the scrolls: status, dangers, decisions.
  4. /make-camp The session ends by writing everything back: journal entry, lessons, XP.
  5. /complete-quest The quest's lessons distill into project-wide memory for every future quest.

Side quests

Mid-work you spot a one-line bug that has nothing to do with today's focus. Fixing it now derails the session; ignoring it loses it forever. Side-quests are the third option.

  1. /side-quest "avatar border clips" Captured in one scroll. Your active quest does not change.
  2. (another chat) open the NOTE Another chat — even another day — picks it up by name; one scroll holds everything it needs.
  3. /close-side-quest What was learned distills UP into the parent quest's scrolls.

Install

  • Plain markdown files + slash commands. No server, no database, no build.
  • Everything lives in .ai-context/ in your repo — committed, reviewable, greppable.
  • vs CLAUDE.md: that's static always-on instructions. Quests are per-feature working memory with a lifecycle — plan, work, record, distill.
  • The RPG flavor lives in filenames and banners. Your code and commits stay normal.

Two commands in Claude Code, then restart and start your first quest. 

/plugin marketplace add findexu/finpack-claude
/plugin install quest-system@finpack-claude

Restart Claude Code, open your project, and run /new-quest. Prefer owning the files? The repo can also be cloned — /install-quest-system bootstraps any project; the README is the canonical install doc.
