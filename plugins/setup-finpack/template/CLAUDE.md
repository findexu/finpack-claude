# Project Instructions

finpack-claude: a Claude Code plugin kit (bash + markdown). No build/test/lint toolchain.

## Commands

```bash
bash scripts/sync-plugins.sh            # source -> per-plugin copies (run after editing source)
bash hooks/tests/run-all.sh             # hook test suite
bash scripts/install-quest-system.sh    # bootstrap quest-system into a project's .claude/
```

## Architecture

- Source of truth: `skills/<name>/`, `agents/<name>.md`, `hooks/*.sh`, `rules/*.md`, `settings.json`, `CLAUDE.md`.
- `plugins/<name>/` are SYNCED copies of source. Never edit directly. Edit source, then run `sync-plugins.sh`.
- `.claude-plugin/marketplace.json` is the catalog; each entry points at `plugins/<name>`.
- `setup-finpack` plugin bundles the whole repo as a template under `plugins/setup-finpack/template/` (rebuilt by sync).

## Key Decisions

- Plugins must be self-contained: Claude Code copies each plugin root to a cache on install and paths can't escape it, so every agent/skill/hook physically lives inside its plugin folder (hence the sync duplication).
- Dual versioning in `skills/quest-system/`: `VERSION` (calver `YYYY.MM.NNNN`, what the update mechanism checks) + `SKILL.md` frontmatter (semver milestone marker). Bump both.

## Workflow

- After editing any source under `skills/`/`agents/`/`hooks/`, run `sync-plugins.sh` before committing — stale plugin copies are the #1 drift bug.

## Don'ts

- Don't edit `plugins/**` by hand — it's generated by `sync-plugins.sh`.
